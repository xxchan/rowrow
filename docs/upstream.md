# Upstream issues and workarounds

When rowrow works around a gap in a dependency instead of fixing it there, the gap is
listed here with its upstream fix, so the workaround can be deleted when the fix lands
(PRINCIPLES.md, engineering 6).

| Where | Gap | Workaround in rowrow | Upstream |
| --- | --- | --- | --- |
| npm 11, and `@earendil-works/pi-coding-agent` (through oar) | npm 11 (seen with 11.12.1; npm 10.9 filters them) installs every optional package a dependency's `npm-shrinkwrap.json` lists, whatever its `os` and `cpu`, with or without `--os`/`--cpu`. pi-coding-agent 0.87.1's lists esbuild for 26 platforms: about 280 MB in every install, where one platform's 11 MB is used | `scripts/build-bundle.ts` removes packages whose `os` or `cpu` rules out the bundle's platform, so the Mac app and the SSH bundles carry one esbuild. `npm install -g rowrow` with npm 11 still gets all 26 | Not reported yet: npm filtering them again, or pi-coding-agent dropping the shrinkwrap, fixes every install |
| `@pierre/diffs` 1.5 | Its `@shikijs/transformers` range allows 4.x, which brings a second Shiki core next to the 3.x that `@streamdown/code` uses | `pnpm-workspace.yaml` overrides `@shikijs/transformers` to ^3.23.0 (`@pierre/diffs` works with either) | Not reported yet: the override goes when `@streamdown/code` moves to Shiki 4 |
| oar 0.45 with pi | Around a replaced system prompt pi still adds its own context: AGENTS.md files (its agent directory's, and those of the directories above Coach's) and its skills catalog (oar's `runtimes/pi/open.js`). Claude's equivalents (the user's MCP servers, settings, hooks, CLAUDE.md) stay out through `SessionOptions.launchArgs` (`LAUNCH_ARGS` in `src/server/coach/tools.ts`), which pi refuses | None: Coach on pi reads them | Not reported yet: an oar option for pi's `noContextFiles` (and its skills) |
| oar 0.45 | oar doesn't report a session's effective tools, so a tool `disallowedTools` missed (a misspelled or new built-in), or an MCP server claude's launch flags didn't keep out, would go unseen | `leakedTools` (`src/server/coach/tools.ts`) reads claude's native `system/init` frame (`native.tools`, claude's format, not oar's contract): any tool besides `mcp__rowrow__*` logs `coach.tools_leaked` and puts "Coach's session has tools it shouldn't: …" in the chat. A safety net now: with the flags, claude 2.1.292's init listed rowrow's tools and server only (2026-10-09) | TODO: read oar's effective tool list instead when oar#253 lands, which covers pi too |
| claude 2.1.292 | `--setting-sources` loads a settings file whole or not at all: Coach can't keep the user's sign-in (the file's `env`, its credential helpers) and leave their hooks, permissions, plugins and the rest out | `src/server/coach/claude-settings.ts` reads the user's settings file and passes its `env` in the run's environment and its four credential helpers in `--settings`; other sign-in keys (`proxyAuthHelper`, `forceLoginMethod`…) don't come along | Not reported yet: a claude flag that loads a source's sign-in keys only would let this go |
